## SF height limits (added 2026-11-15)

`parcels.geoparquet` now carries the Planning Code height limit for each lot from DataSF Height and Bulk Districts (`h9wh-cg3m`): `height_district`, `height_limit_ft`, `height_limit_m`, `height_special_plan`, `height_open_space`. 153,143 lots have a numeric limit (median 40 ft, max 1,000 ft). 1,036 are in districts set by a special plan, including 510 in OS open space, and 848 have no height district.

## Submerged parcels (fixed 2026-11-15)

SF land use codes many bay and ocean tideland parcels `VACANT`, so 772 of the 4,582 "vacant" lots were
mostly under water and were being offered to the backend as candidate sites. A lot that is at least 50% inside
Census TIGER 2024 water areas for SF (`tl_2024_06075_areawater`) is now flagged `submerged` and is no longer
`source_indicated_vacant`; its `vacancy_evidence` says so. **Vacant candidates: 3,810 (3,809 published)**, down from 4,582.
27 piers with recorded uses stay `not_vacant` and are only flagged. Every lot carries `water_fraction`.

## Data facts that affect other workstreams

- **Parcel IDs** are `sf:<mapblklot>`. 227,968 active APNs consolidate to 155,028 physical lots, 9,466 of which have multiple APNs (condos). 262 API records have neither `mapblklot` nor geometry and are dropped. All remaining lot geometries are valid.
- **Vacancy** combines the explicit 2023 `VACANT` code with the current land-use snapshot (c5ge-t6pj, 2026-08-17), which has no vacancy code of its own. 3,810 lots are `source_indicated_vacant` (3,809 published) after removing submerged lots, 2,933 are `unknown` and 148,285 are `not_vacant`. 3,187 lots coded vacant in 2023 now record use and are treated as developed since.
- **One lot key is outside the API contract:** `4591A011*` contains an asterisk and fails `ParcelID` `^sf:[A-Za-z0-9_-]{1,64}$`. `publish` omits it. Backend's live provider builds `sf:{mapblklot}` the same way, so it will produce this ID too.
- **v3 `query.json` endpoints need an app token** (403 without one). The pipeline uses the keyless v2.1 `/resource/<id>.json` endpoints for the same datasets.
- **Assessor:** the 2025 closed roll matches 211,163 active APNs. 16,543 active APNs have no roll row; their values stay null.
- **Review predictions are clamped at log1p = 0.** Unclamped model outputs could be negative, which the backend schema correctly rejects.
- **SF host moved:** `data.sfgov.org` now returns 301 to `data.sf.gov`. Backend's parcel provider should use the new host.
- **Reviews coverage is tiny.** 213,536 parsed reviews cover 6,108 place IDs, but only 139 of them are in the Places export. `review_summary.parquet` is therefore nearly all zeros, and joined review counts measure sample coverage only. 42,184 reviews have rating 0 (no star value) and are excluded from `mean_rating`.
- **Schools have no review signal.** `reviews_count` is 0 for every school record (476 labeled rows across all three cities), so school is marked as a degenerate target. School review activity is null with `source = unavailable`, rather than a fabricated 0.

## Category mapping decisions for team review

See `category_audit_sample.csv`; the `reviewer_verdict` column is empty for manual review.

- **Clinic includes individual "Doctor" listings** (11,593 Bay Area rows). The sample contains non-clinic providers (`JD`, `MFT`, `OD` suffixes), and 80% of clinic rows have 0 reviews. Keeping "Doctor" inflates clinic supply in 2SFCA. Dropping it would shrink clinic supply to facilities. Decide before freezing.
- **Pharmacy includes individual pharmacist listings** (e.g. personal names under category "Pharmacy"). These are probably duplicates of the store they work in.
- **Convenience stores are excluded from grocery** (1,669 + 59 rows). Lookalikes such as "Popeye's Tobacco & Grocery" stay `other`.
- Specialists (surgeons, cardiologists, oncologists), acupuncture, PT and med spas are `other`, not clinic.
